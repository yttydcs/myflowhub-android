# Android（hubmobile）：升级 myflowhub-core 到 v0.3.0（对齐 Pipe 抽象）

## 变更背景 / 目标
- Core `v0.3.0` 引入 Pipe 抽象（`core.IConnection.RawConn()` → `core.IConnection.Pipe()`），属于重大变更（Breaking Change）。
- Android 仓库的 `hubmobile` 模块仍固定 `myflowhub-core v0.2.1`，与当前生态（Server/SubProto 已逐步对齐 `v0.3.0`）存在版本口径差异。

目标：
- 将 `hubmobile` 的 `myflowhub-core` 依赖升级到 `v0.3.0`，并确保 `GOWORK=off` 下可编译/可测试。

## 具体变更内容
- `hubmobile/go.mod`：
  - `github.com/yttydcs/myflowhub-core v0.2.1` → `v0.3.0`
  - `go mod tidy` 过程中联动更新部分 indirect 依赖（例如 `myflowhub-subproto/auth` 版本对齐 Server 的依赖口径）
- `hubmobile/go.sum`：更新校验和

## 对应计划任务映射
- `ANDDEP0`：归档旧计划并建立新计划
- `ANDDEP1`：升级 Core 依赖到 `v0.3.0` + tidy
- `ANDDEP2`：`GOWORK=off` 回归测试

## 关键设计决策与权衡
- 保持 `hubmobile/go.mod` 的 `replace github.com/yttydcs/myflowhub-server => ../../MyFlowHub-Server` 不变：
  - 该 replace 与 Android CI（checkout 到 `repo/MyFlowHub-Android` / `repo/MyFlowHub-Server`）的目录结构一致；
  - 本次仅做依赖升级，不引入额外发布策略变更。

## 测试与验证方式 / 结果
- `cd hubmobile; GOWORK=off go test ./... -count=1 -p 1` ✅

## 潜在影响
- `hubmobile` 最低 Core 依赖提升到 `v0.3.0`；若下游强制锁定更低 Core 版本将发生依赖冲突或编译失败。

## 回滚方案
- revert 本次提交（`hubmobile/go.mod`、`hubmobile/go.sum` 与相关归档文档）。
